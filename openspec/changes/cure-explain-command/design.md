# Design — Cure Explain Command

## Overview

Design for the delivered `cure explain` baseline (PR #37, branch `feat/explain-command`, sha `2d8c2b1`) plus the operator-directed permission-model unification delivered and proven at HEAD `f684f18`. The design distinguishes the historical baseline from current delivered D29 behavior; only the A18–A25 round-6 remediation remains pending.

## Command architecture

`cure explain <PR_URL>` dispatches to `_explain_flow_impl` (cure.py) through `cure_commands.py` (catalog entry + re-export contract); the entry's JSON `safety` value and human rendering share A17's exact D29 runtime-policy/mode-line description rather than the delivered read-only claim. Flow: resolve the PR → `scan_completed_sessions_for_pr` (newest-first, includes md-less sessions) → session + meta → resolve the authoritative selected `session_dir` and containment-check untrusted `meta.paths` against it (`_session_path_within`) → thread that same `session_dir` through `run_llm_exec`/`run_codex_exec` into both persisted-log resolvers (never derive the boundary from `repo_dir`) → stage per-run auth (`_stage_review_auth_support`, `stage_rf_jira=False`) → resolve codex provider (only codex is accepted; HTTP/gemini rejected earlier at config/exec) → invoke the exact delivered-interactive runtime construction from `prepare_review_agent_runtime`'s Codex branch (`cure_llm.py:1240-1288`): bypass `True`, sandbox/approval `None`, and `build_codex_flags_from_llm_config(..., include_sandbox=False)` → print a loud truthful mode line → fork the base codex session when `meta.llm.resume` exists (`ReviewflowError` fork failure → inline mode; raw rollout-discovery `OSError` converted per A21) → call `run_llm_exec` without explain's `sandbox_mode` override, removing the inline explain-triggered sandbox/search filter path; when the explanation uses the fork (`codex exec resume`) variant, bypass `_resume_compatible_codex_flags` and forward the runtime flags directly in the same order as interactive `build_codex_resume_command`, preserving `--search` and every other interactive-forwarded flag, while retaining `normalize_artifact=False` → register `explains[]` entry under the sidecar lock and print its expected path only after the artifact gate (non-empty file, per A19/F2) → optional `--open-in-codex` interactive resume in the session repository, with `_open_interactive_codex_resume` reworked from bare `codex resume <fork>` to the same `build_codex_resume_command` semantics as interactive resume: directly forwarded ordered runtime flags (including `--search`), config overrides, bypass-on construction, and the review run's staged `GH_CONFIG_DIR`/`JIRA_CONFIG_FILE`/`NETRC` pointers in the env; every pointed-to staged file is retained for the full interactive resume and cleanup is guaranteed after both successful and failing exits. The shared runtime has no sandbox/approval/bypass config surface today and D29 does not create one. Historical sha `2d8c2b1` instead forced read-only, filtered explain sandbox/search flags, stripped those handoff pointers, and cleaned staged paths before handoff; D29 superseded that baseline and is delivered at HEAD `f684f18`, with implementation/proof recorded in `progress.md`, A9/A14/A17 final, the exact A17 catalog copy live, and `tests/test_explain_runtime_policy_live.py` the live proof owner.

## Prompt design

`prompts/explain.md` addresses a developer who has NOT seen the PR/codebase/review: explicit reader persona, inline first-use glosses, one-clause "what it is" after file/module names, product-level consequences, examples only when the review/PR provides one (else a labeled "Think of it like …" analogy — never invented facts), direct answer first for `## User's question` blocks, and banned internal-prompting mentions. Fork-mode prompts carry `EXPLAIN_RESUME_CONTEXT_NOTE` (the review is already in the fork's context and must not be re-produced).

## Session metadata concurrency design

All session-meta writers converge on one protocol:

1. **`mutate_session_meta(meta_path, *, fn, quiet)`** (cure_sessions.py): sidecar flock (`_session_meta_lock_path` = `sandbox_root/.<session>.meta.lock`, OUTSIDE the session dir so it survives deletion) → fresh reload → `fn(fresh)` mutates in place, returns bool changed → persist only if changed → return merged doc for re-adoption. Strict: raises on missing or corrupt `meta.json` (no resurrection, no corrupt-data replacement). Callbacks must never nest writers (flock is not reentrant).
2. **`SessionProgress`** (cure.py): `meta` is a property capturing a DEEP baseline at adoption; every flush diffs the working copy against the baseline — only changed top-level keys are overlaid, only `deleted_keys`/baseline-absent keys are popped (merge mode intersects `_PROGRESS_MERGE_KEYS`); no-op flushes skip the write; `init()` is the sole full write (creates the doc); flushes skip silently when the file is missing or unreadable (no resurrection). `drop(key)` declares deletions; `done()`/`error()` re-add their keys through the overlay.
3. **Writers routed through the protocol**: follow-up flow (paths, tool-proof persist via `_FOLLOWUP_FLOW_OWNED_META_KEYS` overlay, followups append), resume flow (drops + progress), `_mark_resume_noop_completed`, interactive-resume builder (`meta_updates`), `_persist_normalized_session_verdicts` (recompute on fresh, write-if-changed, refresh caller copy), `cure_output.ChunkhoundLiveProgressReporter` (`drop("live_progress")`).
4. **Deletion coordination**: `clean_session` and `_delete_cleanup_sessions` take the same sidecar lock around `rmtree`; writers re-check existence INSIDE the lock before writing.

**D31 — level-uniform mapping merge ownership (implemented for A23):** writers apply a recursive three-way merge `(fresh on disk, writer baseline, writer working copy)` uniformly at the top-level entry and every nested mapping level. An absent baseline value is treated as an empty mapping for merge purposes whenever both fresh and working contain mappings: if two writers add a mapping at that position, their different members are recursively unioned; if only the current writer adds it, that mapping is adopted. Unchanged writer members leave fresh concurrent values untouched; writer-added/changed members overlay only that member; writer-deleted members are removed. If both writers set different values at the same leaf, the current writer wins; non-mapping leaves (including lists and scalars) likewise remain writer-owned and replace wholesale. `SessionProgress` applies this same entry rule to changed mapping-valued progress keys (notably a baseline-absent `phases` root), while `_persist_followup_meta` applies it to mapping-valued owned fields (notably baseline-absent `llm` and `codex`) against the follow-up flow's initial deep baseline. This preserves different-member concurrent updates at every depth without inventing list reconciliation or weakening explicit deletion semantics.

## Codex execution design

`run_codex_exec` (cure_llm.py) centralizes command construction, event capture, retry isolation, and artifact finalization for both inline and resume modes. Its caller supplies both the execution `repo_dir` and the independently resolved authoritative `session_dir`; display/event log defaults and persisted values resolve relative to and are contained by only that session authority, so persisted `repo_dir` shape cannot widen or narrow the boundary:

- Per-run events file `codex.events.<32hex>.jsonl` (sealed: slice `[0, size-at-end]` stays valid for usage extraction and chunkhound tool-proof).
- Dashboard branch: `ReviewflowOutput.run_logged_cmd` (sink + `drain()` in `finally`). Direct branch: `CodexJsonEventSink` + `run_cmd`, `drain()` in `finally` for EVERY attempt.
- Trust-error retry (`skip-git-repo-check`): a FRESH per-attempt events file (new run token) + fresh artifact-capture state; the failed attempt's `--output-last-message` output is reset at the retry boundary; retry success returns only the retry file (failed file unlinked); retry failure removes the retry file and restores metadata pointers.
- Process-group teardown (finding F6, in scope via A22): `run_cmd`'s untagged path (run.py:1018-1022) starts a new session but re-raises on `BaseException` without terminating the process group; the fix terminates the group (killpg — `_terminate_pipe_holder_group`, run.py:751) before re-raise or passes an `OwnedProcessRegistry` from explain, and `run_codex_exec` retry cleanup becomes `BaseException`-aware.
- `fork_codex_session`: finds the base rollout under `CODEX_HOME/sessions/YYYY/MM/DD`, rewrites the session id in a copy; malformed first record / non-object JSON → normal fork failure → inline fallback (per-record tail validation deferred, D27).

## Credential staging design

`_stage_review_auth_support` (cure.py + cure_llm.py copies): per-run private root `work_dir/.auth-<uuid>` registered BEFORE any copy; gh/jira/netrc staged under it; `rf-jira` helper written to `work_dir/rf-jira` (fixed path — known race, finding F9, in scope via A25: move under the UUID root, register before write); cleanup via `cleanup_sensitive_staged_paths` (idempotent, missing-ok, catches failures). `prepare_review_agent_runtime` owns cleanup of its staged paths on any post-staging exception (round-5 fix). For the D29 explain handoff delivered at HEAD `f684f18`, the outer lifecycle owner retains the staged gh/jira/netrc targets until interactive resume exits and cleans them on both normal return and exception; the historical sha `2d8c2b1` cleanup-before-handoff behavior is superseded. The `rf-jira` helper itself resets `NETRC` to the real home (known deviation, finding F9, in scope via A25: respect an already-staged NETRC).

## Discovery design

`scan_completed_sessions_for_pr` / `resolve_resume_target` / `scan_interactive_review_sessions`: collect done sessions newest-first WITHOUT discarding md-less sessions; `HistoricalReviewSession.review_md_path: Path | None`; verdicts resolved only when the markdown exists; consumers (explain, `pr --if-reviewed=latest`, follow-up dispatch) raise clear errors naming the session when its artifact is unusable; pickers render a "(no review markdown)" marker.
