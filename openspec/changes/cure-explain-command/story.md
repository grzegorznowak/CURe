## Purpose

A developer runs `cure explain <PR_URL>` (optionally `--explain-prompt "<question>"` and `--open-in-codex`) to receive a newcomer-first, review-grounded explanation of a completed review — inline from review text or forked from the original Codex session with full-context replay when Codex produces the artifact (the round-6 missing/empty-artifact limitation is fixed by the absorbed F2/A19 work). Explain uses the same runtime-policy construction as delivered interactive sessions: bypass is on, sandbox mode and approval policy are `None`, configured sandbox flags are suppressed, and no sandbox/approval/bypass configuration surface is added. Every run announces those effective values loudly, retains per-run credential staging and the codex-only backend, and keeps concurrent explain/resume/follow-up metadata updates correct within the locked A11/A12 top-level merge contract extended by the absorbed nested deep-merge fix (with the explicit D27 exclusions and the D28-recorded F1–F9 remediations). This story absorbs the delivered PR #37 work and the delivered operator-directed permission-model unification at HEAD `f684f18` (implementation and proof recorded in `progress.md`; A9/A14/A17 final, A17 catalog copy live), and, by operator decision 2026-08-13, tracks the pending round-6 findings F1–F4 and F6–F9 (A18–A25); by operator decision 2026-08-15 it also absorbs the round-7 regular-usage findings G2/G3/G4/G6/G7/G12/G13 (A26–A32), while findings requiring explicit operator/attacker action or crafted/imported external data (G1, G5, G8, G9, G10, G11) remain out of scope.

## Acceptance

- A1: `cure explain --help` shows the `pr_url` positional (like `cure pr`) and `--explain-prompt`; `cure explain <PR_URL>` requires no flags.
- A2: After a zero-exit default-prompt Codex run against a completed session, explain records an `explains` entry with `prompt_source: builtin:explain.md` and prints the expected `explain/explain-<ts>.md` path and explanation only when that path contains a non-empty artifact; a missing/empty artifact raises a clear error / nonzero exit with no entry and no path output, as specified by A19. (Historical baseline: delivered sha `2d8c2b1` did not enforce this gate; superseded by A19.)
- A3: `--explain-prompt` appends the user's question to the builtin explain prompt (`## User's question` block, landing after the review in inline mode); the builtin loader IS called (template stays the base); entry `prompt_source: user:explain_prompt` and records the `question` text. Default and question-mode prompt construction is active in both inline and fork paths, and no enabled path sends any unresolved token from the Fail-open Checks forbidden-token set to Codex.
- A4: No completed session or invalid PR URL → exit 2 with a ReviewflowError message.
- A5: Live output unless `--quiet`/`--no-stream` (active output controller registered; display lines reach stderr while the LLM runs). Delivery is codex-item-granular, not per-token: codex `exec --json` emits whole completed items, so a single-message answer arrives as one chunk at the end; per-item messages and codex `error` items (rendered as `Codex notice: …`) surface live. The codex CLI is the only LLM backend (OpenAI/OpenRouter HTTP providers are removed and rejected with a clear error).
- A6: Codex provider + recorded `meta.llm.resume` → a forked rollout with a new id is created; `codex exec resume <fork>` runs; base rollout is byte-identical; `meta.llm.resume` still names the base; entry records `resume.mode=fork`.
- A7: Codex with no resume info, a missing/unforkable base surfaced as `ReviewflowError`, or a raw rollout-discovery `OSError` converted to `ReviewflowError` per A21 uses inline mode (prompt contains the review text), creates no fork, and exits 0. Non-codex providers are rejected at configuration/execution. (Historical baseline: delivered sha `2d8c2b1` allowed the raw `OSError` to escape; superseded by A21.)
- A8: `cure commands` catalog contains an `explain` entry.
- A9: Explain uses the same runtime-policy construction as delivered interactive sessions at the `prepare_review_agent_runtime` Codex branch: `dangerously_bypass_approvals_and_sandbox=True`, `sandbox_mode=None`, `approval_policy=None`, and `build_codex_flags_from_llm_config(..., include_sandbox=False)` suppresses configured sandbox flags. Inline explain removes its own `sandbox_mode` override and resulting explain-specific `--sandbox`/`--search` stripping. Fork explain forwards the same runtime flags directly, in the same order, as `build_codex_resume_command` does for interactive resume; explain's fork path does not apply `_resume_compatible_codex_flags` or any explain-specific stripping, so all interactive-forwarded runtime flags except those the `codex exec resume` subcommand does not support survive (the `--search` survivor clause is superseded by A26/D33). A loud startup mode line names the effective sandbox mode, approval policy, and bypass state; staged credentials are cleaned on every failure path.
- A10: Repository selftest (`selftest.sh` Story 26 smoke) passes with the new catalog; `explain_flow` is exported via `cure_commands.__all__`, the `cure` re-export, and the reexport contract test.
- A11: Concurrent explain + resume: explain's progress flushes never restore `status="done"`/`completed_at` over a resume's `status="running"`; resume's `drop()` deletions survive; explain's own phase/status changes still persist.
- A12: Concurrent writers never lose registry entries: parallel explain runs preserve each other's `explains[]` appends; follow-up/resume persistence preserves concurrent `explains[]`/`followups[]`; missing or corrupt `meta.json` is never silently replaced and a deleted session is never resurrected by a writer.
- A13: Session discovery selects the newest completed session first even when its review markdown is missing, and reports the unusable artifact clearly (naming the session) instead of silently falling back to an older session; all auto-selecting consumers (explain, `pr --if-reviewed=latest`, follow-up dispatch) follow this contract.
- A14: `--open-in-codex` after a completed fork-mode explanation invokes interactive resume with that fork id in the session repository through the interactive resume-builder semantics: runtime flags are forwarded directly in order (including `--search`), config overrides are retained, bypass is present per the delivered-interactive runtime policy, and the same staged `GH_CONFIG_DIR`, `JIRA_CONFIG_FILE`, and `NETRC` pointers as the review run are carried in the environment. Every pointed-to staged credential file exists for the full duration of the interactive resume and is cleaned after both successful return and raised failure; command-construction parity and credential lifetime/cleanup are separate proof obligations in Verification.
- A15: Explain rejects each escaping persisted `meta.paths` variant — `repo_dir`, `work_dir`, and `review_md` — before repository/artifact reads or Codex execution.
- A16: A trust-directory retry uses a fresh events file and artifact-capture state and drains every attempt; on retry success the failed events file is removed and retry pointers are retained, while on retry failure the retry events/output are removed and first-attempt pointers are restored.
- A17: The `explain` entry's safety description is exactly `Same runtime-policy permission model as interactive sessions; effective sandbox/approval/bypass announced at run start.` in `cure commands --json`, and the human `cure commands` catalog renders that same description. This safety-copy accuracy is independent of A8's entry-presence obligation.
- A18: Explain/log resolvers validate the effective write target derived from persisted `meta.logs.codex_events` and `meta.logs.codex` against the authoritative selected-session directory already resolved by the flow, never a boundary derived from persisted `meta.paths.repo_dir`; they reject any target that escapes before any write, mkdir, or open. This holds when `repo_dir` equals the session root, is nested at any depth, or is absent/defaulted. For `codex_events`, it includes directory-shaped persisted values (`.` and the absolute session root) whose generated `codex.events.<token>.jsonl` target would escape. The error is clear and matches the `meta.paths` containment contract. (F1)
- A19: After a zero-exit Codex run, explain requires the artifact path to exist and be non-empty (stripped) before registering the `explains` entry or printing the output path; a missing/empty artifact raises a clear error / nonzero exit. (F2 — supersedes the delivered D28 F2 exclusion)
